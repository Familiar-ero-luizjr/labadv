Modelagem de Banco de Dados · Advogado Já

Modelo de tabelas e relacionamentos proposto a partir das telas e estados presentes nos quatro HTMLs de jornada: Cliente, Advogado, Estudante de Direito e Administrador.

Escopo: isto não é mais um mapa das jornadas. É a tradução das necessidades das telas para uma estrutura relacional de banco. Onde a tela exige dados mas a regra funcional ainda não foi fechada — especialmente permissões administrativas, sanções e ações financeiras — a modelagem aparece como estrutura proposta, sem transformar a regra em decisão de produto.

Inventário proposto

As tabelas estão agrupadas pelo papel que exercem na aplicação, não pela persona que as “possui”.

Importante: telas como Home, Central de Ajuda, avisos e estados visuais nem sempre exigem uma tabela própria. O mapa “Telas → tabelas” mostra justamente quando a tela apenas consulta dados de outras entidades.

Telas → tabelas utilizadas

Uma screenKey sem tabela associada é uma tela informativa ou derivada de dados já carregados; não é justificativa para criar uma tabela artificial.

DDL proposto — PostgreSQL
Administrador: o bloco RBAC (admin_roles / admin_permissions / admin_role_permissions) é uma proposta técnica para suportar as telas de Administradores e Permissões. A definição de níveis, Super Admin e quem pode promover/remover continua funcionalmente pendente.
